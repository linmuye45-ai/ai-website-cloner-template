# Party Lab 功能与部署说明

## 本次增加

- 固定游戏模板现在可切换竞速/团队合作、3 种目标外观、3–25 目标分及 15–90 秒；这不是 AI 生成器。
- 「保存到本机」保存当前配置到浏览器 localStorage（清除数据即丢失）；「分享玩法链接」把数据写入 URL，不依赖服务器、不含昵称。别人能打开、修改并重新分享；URL 是公开文本，不要放敏感信息。仅识别 v1，超界输入回退安全默认值。
- 临时多人房间邀请与玩法分享是两回事：房间需运行服务器且断开/重启后失效；房间邀请包含随机码，不是永久配置，也不是私密访问认证。
- 合作模式累计所有玩家得分，达到目标成功；时间到未完成则失败。任何人中途断开则合作局提前结束，竞速剩余人数不足两人也提前结束。服务器统一校验目标和胜负。
- 房主离开后交由下一玩家接任；已使用颜色不会分配给新玩家。服务限制连接和房间数并增加心跳/未加入超时，但**不是生产级防作弊、身份认证、滥用控制或多实例支持**。

## 本地运行

```sh
npm ci
STATIC_EXPORT=1 npm run build
SITE_DIR=out npm run party
# 打开 http://localhost:3000/party/，另一设备必须能访问该服务器的网络地址
npm run test:party
```

预览通过同源 HTTP/WebSocket，非浏览器代码内部的 localhost 链接；房间与分数仅保存在进程内存。仓库的 `site/` 是用于已有预览和静态归档的构建副本。

## 部署：两种不同环境

- GitHub Pages 工作流部署静态前端，提供单人玩法、规则保存和规则分享；**不提供**多人服务。
- `deploy/party.Dockerfile` 构建一个同时提供静态站与 WebSocket 的 Node 单实例容器，可供支持 WebSocket 的托管平台部署。需自备部署账号/服务、可用的 HTTPS 域名和正确的 WSS 反向代理。示例：`docker build -f deploy/party.Dockerfile -t party-lab .`，`docker run --rm -p 3000:3000 party-lab`。容器构建在本环境未验证（没有 Docker 可执行文件）；它是部署起点而非已上线服务。

上线前必须完成安全审计、细化跨站 Origin 与代理策略、反滥用与活动配额、真实终端及跨网络测试、监控/限费、数据保护和法律审查。单进程重启丢房；横向扩容前要引入房间路由与共享状态。没有生产 SLA。

## 测试记录

`npm run test:party` 使用真实的本机 WebSocket 客户端验证比赛和合作、满房、房主、目标校验、胜负及主持权迁移，并验证分享规则的 Unicode 往返及恶意参数回退。静态构建和 TS/ESLint 检查也运行。额外在本地启动 Chromium，使用 Playwright 验证本机保存后刷新、玩法链接、模拟移动屏幕触控、两个浏览器加入并合作获胜；未发现页面 JavaScript 错误。移动端为模拟，尚未在真实手机、跨网络或真实用户环境测试。可选浏览器测试脚本为 `tests/party.browser.cjs`，需要预先安装 playwright-core、可运行的 Chromium 并启动服务。
