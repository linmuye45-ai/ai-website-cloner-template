# 怪奇搬运局 / ODD HAUL

## 新方向
一个 2–6 人合作的第一人称短局派对原型，朋友一起从怪奇博物馆把脆弱的宝物搬到回收圈，躲避追赶搬运工的馆长。两人可同时抓一件宝物，一人拉太急会积累压力、反复弄坏会输；两人走太远会松手。目标是产生“队友互相协调却手忙脚乱”的时刻。当前仅一个房间场景、三件宝物、一种追逐敌人，搬运是自写简化模拟，不是刚体物理；不是成品，尚无声音、实时语音、公开匹配、Steam 构建或真实玩家验证。

## 参考和区别
- 《Meccha Chameleon》以玩家手绘伪装和搜寻者的信息差为核心（[GameLook 观察](http://www.gamelook.com.cn/2026/06/595655/)）。本原型不复制其绘色或找人规则；借鉴“规则容易理解、玩家创造意外场面”的设计目标。
- [《R.E.P.O.》官方 Steam 页](https://store.steampowered.com/app/3241660/REPO/)介绍最多六人合作、物理物件和小心搬运；本原型参考多人协作搬运的情绪，并非其规模、复杂度或品质，也没有物理引擎或近距离语音。
- 创作目标不是宣称原创机制或保证爆火。需要与直接竞品实玩对比，再观察真实玩家能否自发产生值得分享的时刻。

## 本地运行
Node 24：`npm ci`，`STATIC_EXPORT=1 npm run build`，`PORT=3000 SITE_DIR=out node server/party.mjs`，浏览器访问服务的 `/heist/`，至少两个浏览器连接同一服务并在房间中开始。客户端用同源 `/api/heist` WebSocket，模拟状态由服务端判断；房间和分数只在单个进程内存，进程重启、空房后删除。`node --test tests/heist*.test.mjs` 覆盖规则和真实双客户端协议。浏览器测试需本机 Chrome，部署流水线使用 `tests/heist.browser.cjs`。

## 发布边界
GitHub Pages 是静态托管：公开页面仅可离线单人训练，不提供多人服务。实时多人必须部署和持续维护同源支持 WebSocket 的 Node 服务（或配置同源反向代理），需要公网 HTTPS/WSS、容量/超时/隐私/安全审查。当前临时预览可多人测试但会停止，不是永久联机服务；不得将二者混淆。房间无账号、聊天、持久性、重连、跨实例同步或生产级反作弊。后续需实现真正有趣的物理、关卡与角色动作、语音安全设置、无障碍、真实设备与多人压力测试，并让陌生玩家验证喜剧时刻、合作是否愉快与重玩意愿。
